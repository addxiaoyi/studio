# 模型调用 50 点审计与修复记录

范围：图片/视频模型选择、请求构造、上游调用、队列、扣费、资产落库、画布同步和前端状态。

状态含义：`已修复` 表示本轮已改动并有测试或生产证据；`已有防护` 表示代码已有实现并在现有测试中覆盖；`待补强` 表示需要独立配置、供应商合同或额外端到端证据，不能仅靠静态代码确认。

1. **模型退休过滤**：`已修复/已有防护`。退休模型在路由、工具和 Job 创建前拒绝。
2. **显式模型严格选择**：`已修复`。用户手动选择不可用模型时不静默替换。
3. **degraded 渠道隔离**：`已修复`。图片路由和实际 Provider 查询只使用健康映射。
4. **参考图数量上限**：`已修复`。Agent 输入最多 14 张，Kuaipao 同步网关最多发送 1 张。
5. **参考图单项大小上限**：`已修复`。HTTP/Agent 输入限制为 12 MB，远端读取限制为 25 MB。
6. **未解析引用禁止提交**：`已修复`。引用全部失效时直接返回 `invalid_input`。
7. **Data URI 格式校验**：`已修复`。非法 Data URI 不进入 Provider 请求。
8. **参考图协议限制**：`已修复`。远端引用只允许 HTTP/HTTPS。
9. **参考图读取超时**：`已修复`。远端参考图读取使用 30 秒上限。
10. **参考图响应大小校验**：`已修复`。Content-Length 和实际字节数均受限。
11. **图片比例边界**：`待补强`。部分 Agent schema 仍接受自由字符串，需统一到共享比例契约。
12. **视频时长边界**：`已有防护`。工具、Profile 和 Job schema 多层校验，但需补齐每个 Provider 的真实合同测试。
13. **视频分辨率边界**：`已有防护`。Tier、模型能力和 Provider Profile 均参与校验。
14. **音频能力边界**：`已有防护`。只向声明支持音频的模型发送音频参数。
15. **模型调用 Profile**：`已有防护`。Provider family 使用显式 request/response profile。
16. **Provider endpoint 选择**：`已有防护`。Kuaipao、Gemini、Replicate、Volces 等使用专用适配器。
17. **Provider 输入字段映射**：`已修复`。Kuaipao 双参考图不再原样发送到同步网关。
18. **质量到分辨率映射**：`待补强`。不同 Provider 的质量语义仍需逐模型在线合同验证。
19. **鉴权 Header 传递**：`已有防护`。服务端统一生成 Bearer Header，不向客户端下发密钥。
20. **请求追踪 ID**：`已修复`。图片和配置视频请求带 `x-helstera-request-id` 并写入日志。
21. **请求体大小观测**：`已修复`。图片/视频 Provider 日志记录请求体字节数，不记录提示词和图片内容。
22. **Provider 请求超时**：`已有防护/已强化`。图片 180 秒、视频 30 秒请求超时明确化。
23. **Provider Content-Length 限制**：`已修复`。响应头超过 32 MB 立即拒绝。
24. **Provider 实际响应大小限制**：`已修复`。响应体超过 32 MB 不继续解析。
25. **HTTP 状态分类**：`已有防护`。401、402、404、429、5xx 分别映射为可操作错误。
26. **JSON 解析失败分类**：`已有防护`。非 JSON 响应不会被当成成功。
27. **成功响应结构校验**：`已有防护`。缺少 URL、Base64 或任务 ID 时失败。
28. **Base64/Data URI 输出校验**：`已修复`。生成结果和下载结果均拒绝非法 Data URI。
29. **生成结果下载超时**：`已修复`。图片和直连图片下载均使用 60 秒超时，视频已有独立超时。
30. **生成结果下载大小限制**：`已修复`。图片下载限制为 25 MB，视频使用现有读取上限。
31. **MIME 与对象扩展名一致**：`已修复`。PNG、JPEG、WebP 不再统一写成 `.png`。
32. **异步任务 ID 解析**：`已有防护`。Profile 支持多种嵌套 task ID 路径。
33. **异步轮询总时限**：`已有防护`。Google、Metaso、视频 Provider 都有最大轮询窗口。
34. **轮询退避**：`已有防护`。视频轮询使用递增间隔，避免固定高频请求。
35. **轮询终态分类**：`已有防护`。failed、error、cancelled 和业务拒绝单独处理。
36. **队列可见性续租**：`已有防护`。长任务周期性续租并写入阶段心跳。
37. **队列原子 Claim**：`已有防护`。Worker 使用状态条件避免重复执行。
38. **Job attempt 计数**：`已有防护`。重试次数由数据库状态控制，不由前端猜测。
39. **Job 幂等键**：`已有防护`。HTTP Job 入口支持 Idempotency-Key；Agent 内部仍需补齐跨请求键。
40. **同一运行内重复提交抑制**：`已有防护`。单图提交器按稳定输入合并并保留超时 Promise。
41. **Provider 结果 checkpoint**：`已有防护`。Provider 成功后先保存结果，再下载资产。
42. **对象路径确定性**：`已有防护`。Worker 使用 workspace/job ID 生成固定对象路径。
43. **资产记录 Upsert**：`已有防护`。相同对象路径不会重复创建资产记录。
44. **画布元素幂等写入**：`已有防护`。以 Job ID 检查已写入元素。
45. **Canvas sync_pending 恢复**：`已有防护`。资产成功但画布失败会进入同步恢复流程。
46. **Job 扣费关联**：`已有防护`。队列 Job 扣费记录保存 `job_id` 和交易 ID。
47. **直连图片失败退款**：`已修复`。直连图片在 Provider、下载或存储失败后自动退款。
48. **未知上游结果禁止自动退款/重试**：`已有防护`。避免上游迟到成功造成重复生成或免费生成。
49. **前端 Job 状态恢复**：`已有防护/已强化`。页面恢复最新 Job，状态卡位于消息底部并轮询终态。
50. **可观测性与健康状态**：`已修复/待补强`。请求 ID、输入数量、耗时和大小已记录；仍需接入告警和每 Provider 的长期成功率面板。

## 本轮仍需单独处理

- 11、18、39、50 需要共享契约、Agent 运行上下文或监控系统的独立改动。
- 12、13、14、32、33、34、35 的静态防护已有，但仍需要真实 Provider 合同测试。
- 任何“上游结果未知”的任务都不能仅凭本地超时判断是否应该退款；必须先核对供应商任务记录。
