# 2026-11-14 首次预扣与任务关联原子化

## 行为

- PostgreSQL `generation_deduct` 在同一事务内锁定关联任务、锁定余额、写入扣款账本、关联预扣凭证并冻结价格。任务关联失败会一起回滚余额和账本。
- 与未开始任务的取消共用任务行锁。取消先提交则拒绝扣款；扣款先提交则取消读取到完整的预扣金额，现有退款路径可释放该金额。
- 已有扣款的重复请求不再次扣费，支持修复历史未关联凭证；不同账户不能使用别人的任务 ID，重试金额与原始账本金额不一致时返回 409。
- 已结算任务重放原始扣款不会覆盖最终金额或结算回执。没有后台任务行的 Agent 消息计费保留原行为。
- `setCreditsInfo` 保留兼容重放入口。付费任务仍必须存在匹配的预扣凭证才能被队列和 Worker 领取。

## 取消与退款的原子提交

- `cancelUnstartedJob` 在任务行锁内再锁余额，核对原始预扣归属、金额、已有退款和结算调整，写入退款账本与取消状态后统一提交。HTTP 层不再另起一次退款调用。
- 已取消且尚未执行过的历史任务可重试取消，补齐缺失退款；已有全额退款只返回原金额，不再次入账。
- 在途任务仍仅记录取消请求；有供应商结果、开始记录或结算回执的任务不能按未执行退款。账本异常返回核验错误，不凭任务金额直接补钱。
- 新增真实数据库回归先复现了两个缺口：取消完成但余额仍为 97；注入退款写入失败时取消依然成功。修复后计费协调 30 项、试穿 9 项，共 **39/39** 通过。
- 补充断言覆盖：五个并发取消只退款一次、历史已取消漏退款重试、退款写入异常整体回滚、取消状态写入异常整体回滚、结算后任务状态/次数被重置不能再次退款。
- Server 类型检查通过；取消/任务服务/时间线定向单元测试 20/20 通过，补充保护后取消单元测试 2/2 重跑通过。
- 本段改动发生在远端迁移演练源码快照创建之后；演练不代表这些最新 Server 代码已经构建或部署。
