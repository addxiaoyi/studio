# 2026-11-14 生成任务恢复与历史取消退款

## 实际行为

- 图片和视频创建接口重试时核对工作区、工程、画布、会话、模型、提示词、参考素材和视频参数；不同参数复用原请求标识返回 409。待预扣任务继续走费用确认，扣费后返回数据库中的最新状态。
- HTTP 创建接口延后审批消费，先以稳定请求标识建立或恢复任务，再锁任务关联审批并预扣。相同审批并发提交指向同一任务；普通确认接口也沿用原请求标识或 `reservationJobId`，不另建剪辑或生成任务。
- 新增迁移 `20261114000006_approval_context_scope.sql`，待确认报价按完整上下文去重，隔离不同工程、请求与恢复任务。
- 新增迁移 `20261114000007_reservation_approval.sql`，保存实际资助任务的 `billing_approval_id`。扣费事务核对调用方审批 ID，冻结对应价格；已有扣款后禁止更换审批。预扣失败重新报价时，旧审批不会成为新扣款的计价依据。
- 明确拒绝缺失价格快照的历史审批，返回 409，余额和账本回滚；不会按当前模型价格补造历史快照。
- 已取消任务保持终态；低层任务创建和队列通知不再重新入队已取消任务。队列与领取门禁阻止已退款凭证再次执行，包括未标记 `billing_required` 的旧任务。
- Worker 启动及每分钟处理至多 100 个已取消、未开始、有扣款无退款的任务，沿用原子退款操作。账本不一致标记 `cancel_refund_review_required`，不猜金额；临时错误报告任务编号并移至下一批处理顺序。
- 网页视频显示独立待预扣状态，提供恢复原预扣和取消入口；试穿明确提示补足余额后恢复。刷新和轮询只查询状态；用户点击恢复才重试确认。前端核对恢复返回的任务 ID，不覆盖原任务。
