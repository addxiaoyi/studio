# 2026-11-14 超额结算确认

## 已实现

- 超额结算先保存 `settlement_review` 和已生成结果，保留原预扣余额，等待用户明确确认。
- 任务详情与视频生成面板展示原预扣、总额、补扣差额和拒绝入口。接口绑定登录用户、任务 ID、具体确认 ID，拒绝陈旧确认。
- 确认后的账本操作仍调用事务结算器；五个并发确认只写入一笔差额，重复请求不再次扣款。
- 拒绝后保持拒绝状态，不自动重新批准。用户可在同一界面重新确认。
- 确认只恢复已生成结果的同步，不派发新的生成任务。手动同步也不能跳过未消费的费用确认。
- 工作流额外费用确认会锁定原运行预算，检查其他预留之和并更新原预留金额；超预算时拒绝补扣。
- 账本已提交但交付状态未更新时，再次确认可恢复同步状态，余额不重复变化。
- Worker 在结算需审核时直接停止自动重试，避免重复处理已经生成的结果。

## 已验证

- PostgreSQL 结算回归 18/18：包括待确认、拒绝、并发确认、HTTP 鉴权、陈旧确认、预算限制、同步绕过防护和丢失响应恢复。
- Web 确认组件与视频恢复测试 15/15；原同步/时间线测试 9/9。
- 六个工作区包类型检查通过。部署/CI 配置测试 40 项运行，38 通过、2 平台跳过。
- 完整 Worker 进程回归 5/5 通过：超额后执行器调用、供应商提交和文件生成均为一次，保留原余额并进入待确认；其余退出/重启恢复用例同时通过。初次运行因新增测试 SQL 参数类型错误失败并污染后续队列，修正参数后重跑整组通过。

## 边界

本轮使用隔离 PostgreSQL、受控生成结果和组件测试，尚未进行安装包或生产浏览器验收。跨供应商账单核验与自动审批价格快照仍待完成。拒绝补扣保留原预扣，最终退款需依据供应商回执处理，不承诺拒绝即退款。
